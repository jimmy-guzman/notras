# DESIGN

Interface conventions for notras. Every rule here is either implemented in `src/styles.css` or observable in the running app. `AGENTS.md` maps the rest of the docs.

## Operating principles

- **The window is the editor.** There is no sidebar and no note list on screen. Anything that is not the note reaches it through ⌘P, ⌘⇧P, a dialog, or the status strip. The one exception is the tab strip, which carries the open set and the controls acting on it: opening, selecting, closing and reordering a tab (`D52`), and after it the find button, a door into ⌘P for a hand on the mouse (`D88`). Renaming, moving, pinning and tagging act on the note rather than the tab, so they stay in the palette, and finding a note is still the palette's job. The two bands carry the note's state and the editor's view state.
- **Keyboard first.** Every action has a shortcut or a palette entry. A feature reachable only by mouse is unfinished.
- **Case by role.** Controls and titles are lowercase, prose is sentence case, and xs section labels are uppercase through CSS (`D84`).
- **Default to less.** Add nothing that does not earn its place, then remove one more thing. A new bar item is the last resort; the palette is the first, and one that arrives displaces something rather than joining it: the tab strip took the title's place in the band rather than adding a band (`D52`).
- **The last five percent is the work.** A feature that renders but reflows the caret, dims the wrong block, or teleports the text on toggle is not shipped.
- **The same problem gets the same solution everywhere.** A second implementation of something the app already does is a bug in the design. A second entry point into one implementation is not: tags are a status-strip picker and a palette view over one `changeNoteMetadata` (`D31`), and pin is a palette row and ⌘⇧D over the same call.
- **This is a macOS app.** Where a convention of the platform and a convention of the web disagree, the platform wins. Rounded controls, a blurred backdrop, and a dialog that scales on open are native behaviour.

## Typography

The app uses Tailwind's default system font stacks without overriding them in `src/styles.css`:

| Token | Face | Job |
| --- | --- | --- |
| `--font-sans` | Tailwind's default sans-serif stack | Interface, prose, headings, and welcome wordmark |
| `--font-mono` | Tailwind's default monospace stack | Code and data, inside the editor and out |

Both stacks resolve from the platform and installed fonts. The app bundles no font files. Print uses the same font roles as the editor.

- The editor column is `max-w-2xl`, with 24px horizontal padding and `1.65` line-height. Prose and headings use the system sans face on screen and in print.
- **The note surface is a shadcn/typeset preset** (`D40`). `.typeset-note` in `src/styles.css` sets three rhythm controls, body and heading roles sharing sans, a mono role, and one hairline, and the list indent and every block gap derives from them. Tuning the reading surface means moving `--typeset-size`, `--typeset-leading`, or `--typeset-flow`. The heading scale is the one exception.
- **The note reads at 16px across window widths and in print,** at the default root size. The preset uses `--typeset-size: 1rem` and sets `font-size` from that token without the vendored multiplier.
- **Code size is independent of prose size.** Fenced code and source mode use `0.875rem` and `1.5` line-height. Inline code uses `0.9em` to follow the sentence around it.
- Headings scale from the body size: `1.88em`, `1.56em`, `1.33em`, then body size for h4, h5 and h6. The ratio is 1.2 a step and stops at h3, which is where a note stops needing ranks. One weight, 600, and one ink, `--foreground`, serve all six, so size alone ranks them, and each takes the same air as any other block: one line, divided back down by the level's scale so it does not grow with the heading.
- Both bars set `text-xs` once, on the titlebar and the footer, and everything in them inherits it: tabs, the overflow count, tag chips, the word count. Palette metadata takes `text-xs` too, and other UI text inherits the base size. Do not invent a per-component size. The sizes in hand-written CSS for floating surfaces, the code-block toolbar, and source mode are not precedents.
- Mono carries code and machine text, including a suggestion's shorthand hint. The welcome wordmark and README hero use system sans.

## Color

Blackout pairs a warm near-black writing surface with softened ivory text and a charcoal shell. The palette takes its warmth from paper and analog inks. Pink identifies actions and focus; softened cyan and violet carry the outrun influence through syntax and active rows. The light scheme uses ivory paper and dark ink. `src/styles.css` owns the interface's exact color values in both schemes.

| Role | Tokens | Appearance and use |
| --- | --- | --- |
| Workspace and frame | `--background`, `--shell` | The note sits inside the shell used by the titlebar, status strip, and outer frame |
| Code and floating surfaces | `--card`, `--popover` | Inline code and code blocks share a darker surface than the dark workspace; floating surfaces are lighter. Both use the same near-white surface in light mode |
| Neutral controls | `--secondary`, `--muted` | Secondary controls, neutral hover fills, and pressed toggles |
| Active rows | `--accent`, `--accent-foreground` | Violet highlights in command and menu rows, with body ink |
| Actions and focus | `--primary`, `--primary-foreground`, `--ring` | Pink actions, checked tasks, and focus indicators |
| Text | `--foreground`, `--muted-foreground`, `--faint` | Body and secondary ink; placeholders share secondary ink |
| Text selection | `--selection` | Blue selection with body ink, including selected syntax and input text |
| Edges | `--border`, `--input` | Border matches the shell; input edges have their own stronger neutral |
| Status | `--success`, `--warning`, `--info`, `--destructive` | Green success, amber warning, cyan information, and coral-red errors |

- The system chooses the scheme. `:root` defines dark, and `@media (prefers-color-scheme: light), print` supplies light values. The app has no theme toggle, and print uses the light palette.
- Ghost buttons use `--muted` on hover, at 50% in dark mode. Toggles use the full muted fill on hover and while pressed. Active tabs retain the workspace fill. These states keep neutral surfaces and body ink.
- Note links inherit the surrounding text's color and weight at rest and use `--primary` on hover. Pink also supplies syntax declarations and selected table-cell tints.
- Status toasts use their status ink for the title and icon, body ink for the description, and a 7% Oklab mix of status ink into `--popover` for the surface. Default and loading toasts use the popover surface without a status tint.
- Derived tints use `color-mix` against tokens. Selected table cells use primary at 12%, and unchecked task boxes use foreground at 25%.
- Syntax highlighting uses twelve named roles, `--syntax-comment` through `--syntax-type`. Declarations use pink, control flow coral, imports and tags violet, functions and members blue, numbers amber, strings green, and types cyan. Operators use body ink; comments and punctuation use secondary ink. Shiki maps scopes to these roles and keeps syntax at regular weight without syntax-driven italics (`D73`).
- `color-scheme: dark light` in `index.html` and the base layer supplies the appearance for native controls and the webview's initial canvas.
- The note and source editors use shadcn's ScrollArea (`D76`). Its viewport owns scrolling, its thumb uses the border color, and focus mode hides it.
- Launch backgrounds are also declared in `index.html`, `tauri.conf.json`, and `lib.rs`, since those layers paint before the stylesheet loads (`D27`). `src/styles.spec.ts` checks them against the page tokens.

`src/styles.spec.ts` checks declared text-on-surface pairs against its contrast thresholds, token parity between schemes, and equality between the shell and border colors. These assertions cover the pairs named in the test, not every rendered component state.

## The icon

The icon pairs a calm writing surface with an expressive backdrop. An ivory front note carries three gray strokes over a warm rose rear note with a narrow coral edge. A dark rounded tile carries soft blue lighting along the left edge and pink along the right, meeting through violet. The glow stays close to the perimeter and fades into the charcoal face, leaving the notes prominent. The lighting and layered sheets carry the restrained 80s and cyberpunk influence. The mark has no animated variant.

- The desktop master is `assets/icon-desktop.png`, with transparency outside the tile. The generator cleans the alpha edge and maps the visible tile bounds at 50% alpha to a centered 824-by-824 square within a 1024-unit canvas, preserving the soft fringe outside those bounds. It rounds both margins down to whole pixels at each export size. This corrects the raster tile's slightly rectangular proportions without counting its source padding or fringe as part of the tile.
- `assets/icon.svg` supplies the shared note geometry and vector tile. Small icons through 64 logical pixels use that geometry with stronger seams and writing strokes at smaller sizes. Larger logical sizes use the raster master. Retina representations use stroke weights for their logical size.
- Welcome marks and the README hero omit the tile. Welcome marks and favicons follow the system scheme. Their foreground and background come from app tokens; rear-note colors and edge lighting belong to the artwork. The installed icon and Apple touch icon retain the dark tile.
- The tray derives a monochrome template from the same notes, rendered at 36 pixels for an 18-point slot. Its seam and writing strokes are transparent so the system can tint the silhouette for either menu-bar appearance.
- The welcome lockup uses a 112px mark beside a left-aligned content column, separated by 28px. The column starts with a 48px semibold system-sans wordmark with -0.0375em tracking, then the tagline "write another note" after 8px in 20px system type with 1.3 line-height. Its actions sit 16px below the tagline with 8px between them: a default "new note" button and a secondary "search" button, each carrying its chord. The README hero uses a regular system-sans wordmark and the same single-line tagline.

`pnpm icons` owns the generated family. `README.md` lists the source files and regeneration requirements; `ARCHITECTURE.md` describes output ownership.

## Space and radius

`--radius` is `0.5rem` (8px), and `sm` through `4xl` derive from it in fixed steps. App-owned surfaces use that ladder: tabs, compact toggles, compact buttons, and badges take `sm` (4px), code blocks and images take `md` (6px), and the inset frame and floating editor controls take `lg` (8px). The shadcn components keep the Nova preset's radius rules except `Badge`, which shares the compact control radius across tags, the mentions count, and graph labels, and the `xs` and `icon-xs` `Button` and `Toggle` sizes for the same reason. Circles and pill controls retain their shapes. A shadcn component is restyled in `src/components/ui/**`, never at its call site, which `@shadcn/lint` enforces (`D85`).

**A nested surface takes the parent's radius less the parent's padding** (`D26`). Write it as `calc()` against the parent token, the way `.suggestion-item` and `.link-editor-input` do, so the two curves stay parallel if `--radius` moves.

The bars use Tailwind's 4px spacing unit between neighboring items, including tabs, overflow, new-note and find controls, tags, and view toggles. A text item in a bar insets 6px (`1.5`), the compact inset the code-block toolbar and shadcn's icon-side padding already use: `Badge` supplies it after the `D19` deviation, and the tab, the overflow count and the word count restate it. The 24px icon boxes have no inset to state. Both bands are 32px tall, with a 24px content row and 4px above and below it. Smaller badges and text are centered within the row. The right edge and footer sides use the same 4px inset, and a popup opened from either bar, the tag picker, the mentions list, or a tooltip, lifts 4px off it.

**Every item in the status strip is a shaped item, and the strip sets one gap** (`D36`). The footer is `p-1 gap-1`, a run of like items is `gap-1`, and each item's inset comes from the component it is: a 24px box for the tag control and the view toggles, `Badge` for a tag chip and for the mentions count, and the badge's `px-1.5` on the word count so bare text is shaped like its neighbours. Adding an item means choosing what it is, never overriding a variant's padding to reach a distance.

## Motion

Motion carries a state change and nothing else. There is no decorative animation, no entrance choreography beyond the platform's own, and no spring.

- Focus mode fades non-active blocks to `0.28` opacity over `0.3s`, and a wheel or touch scroll, or a selection reaching past the caret's block, fades them back up until the caret engages again (`D64`).
- Hover affordances (code block toolbar, code block buttons, wikilinks) resolve over `0.15s`.
- Tab background and text changes fade over `0.15s` with `ease-out`, independently of drag movement. Close-icon opacity uses the same duration and easing.
- The editor scrollbar fades in over `0.15s` and out over `0.3s`, using `ease-in-out`. Base UI's scrolling state keeps it visible until `0.5s` after the last scroll, and holding the thumb keeps it visible through a pause (`D76`).
- A dragged tab follows the pointer, and the tabs it crosses slide one place over `0.15s`, as does the released tab and one that ⌘⌥⇧←/→ moves (`D60`).
- Focus mode's recentre glides the note over `0.15s` and yields the moment anything else moves the scroller (`D63`).
- A hop in the graph glides the picked node to the centre over `0.15s` and turns its connecting line with it. Node background, text, and border colors fade over the same duration with `ease-out`; connector colors use the same timing.
- Dialogs, tooltips, and the tag combobox fade, scale, and slide on open and close. This is macOS behaviour for a sheet, and it is the reason the backdrop blurs too.
- Dragged blocks or words follow the pointer under a shadow and their source sits at `0.4` opacity, and neither they nor the bar marking where they land carries a transition, since both track the pointer and that is manipulation rather than a state change (`D71`). Like a dragged tab, they still follow it under reduced motion.
- The window does not bounce. `html` sets `overscroll-behavior: none`, so a flick past the end of a note stays in the note rather than chaining into the document and dragging the titlebar, the tab strip and the status strip with it. A scroller keeps the bounce of its own, which is what an NSScrollView does.

`prefers-reduced-motion: reduce` collapses all of it. Every animation above has a real non-motion end state, so removing the transition costs nothing.

## Interaction and state

- **The window has no native frame.** `body` sets `user-select: none` so text selection outside the editor does not make the app read as a web page. `.allow-select` is the explicit opt-in for anything selectable.
- **The titlebar carries the note's identity** (`D28`): what it is called. It sits in the drag region rather than in a band of its own, so the active tab's label is the note title, resolved as `SPEC.md` specifies (`D52`). Whether it is pinned shows where pinning acts, in the palette's lists (`D88`). It is display-only text: renaming a file is a ⌘⇧P action.
- **A press anywhere in a band moves the window unless it lands on a control** (`D80`). `Titlebar` in `src/components/titlebar.tsx` declares the region both windows render as `deep`, and Tauri treats a button, an input, or a `tab` role as the boundary, so a control needs no class to stay clickable. A control that carries the attribute itself opts back into the drag, which is what the lone tab below does.
- **A tab's padding is not a drag handle** (`D60`). A tab among neighbours marks its box `false` and leaves its label button unmarked, so a press on its padding moves nothing and the label button is the only drag handle. A lone tab puts the region on its label button instead, so pressing and moving it moves the window rather than the tab. With no tab open the strip is its new-note button alone and the press reaches the band.
- On/off controls in the bars use `Toggle` at `size="icon-xs"`. The four view toggles form one `ToggleGroup` with a single tab stop and arrow-key navigation, and they are the only toggles in the bars. Idle glyphs use the bands' `--muted-foreground`. Hover and pressed states use a full `--muted` fill with `--foreground` glyphs, owned by `src/components/ui/toggle.tsx`.
- **A glyph's size follows its role, not its band** (`D51`). A standalone glyph in a bar control takes `BAR_GLYPH` from `src/lib/ui/bar.ts`. An icon beside a word takes 12px, which its button variant usually supplies and the palette's pin marker has to state. Those are the only two roles, so a `size-*` class on an icon anywhere else means the wrong component is wrapping it.
- **Tags are picked from the status strip** (`D30`). A chip reads `#groceries` and filters to that tag; the `Tag` control before the chips opens the combobox, whose vocabulary is the index's own counted tag list. It is built as the new-note button is: an icon-only ghost `Button` named `edit tags` by its tooltip, since the picker removes as well as adds. It leads the run rather than following it, so it stays put as tags come and go and reads as the label of what follows; with none it stands alone. The chips are the only part that shrinks, so they clip before the button or the word count does.
- **Mentions are counted in the status strip**. The chip is a badge shaped like a tag chip, reading `3 mentions` in tabular numerals after the tags, and it is absent while nothing mentions the note, since a zero would be a bar item carrying no information. The chip, ⌘⇧L and the palette's `show mentions` are three doors into one list, whose menu takes the floating-surface recipe below.
- **The title bar starts after the traffic lights.** macOS floats them over the content at the top left, so `--spacing-titlebar` insets everything past them. The value is a platform fact and lives in one place. Windows and Linux put the controls on the right, and would need it mirrored.
- **The titlebar height and the traffic light offset are one decision.** The bar is 32px and `trafficLightPosition` is `{ x: 16, y: 18 }` to centre the buttons in it, so plain centring puts the title on their line and the space above and below them is equal by construction. The offset is carried twice, in `tauri.conf.json` for the `main` window and in `lib.rs` for `capture`, so both move together. Changing the height means rechecking them, and `D29` records what happens when they drift apart.
- **Two bands frame the note, and there is no third** (`D52`). The titlebar above and the status strip below have no dividing borders or inset shadows. Quick capture also has no dividing edge on its titlebar or bottom hint strip. Both windows place the note on an inset `--background` surface within the `--shell` frame. The frame has 4px side margins, an 8px outer radius, and a fixed 4px inner rim; each scroller clips its own content inside the rim, and the scrollbar crosses the rim to ride the frame's edge. No extra vertical margin separates the frame from the bands. With no status strip, the empty workspace leaves 4px below the frame. The rim keeps code blocks separate from the bars while scrolling.
- **The titlebar holds the open tabs, then the find button** (`D52`, `D88`). Both bands use `--shell`, so the note's `--background` reads as its own surface. The find button sits at the right end, where macOS puts search, and is the one mouse route into ⌘P once a tab is open; it stays through the empty state and over an external file, since finding a note is an app action.
- **A tab is a shaped item at the bar rung**: 24px tall and `rounded-sm`, the box the new-note button and the overflow count use. Tabs sit in a `gap-1` run with no divider. The active tab carries the workspace's `--background` and `--foreground`; an inactive tab is transparent in the band's `--muted-foreground`. Tabs divide the strip evenly between `min-w-24` and `max-w-56` and scroll past that, so a lone tab is one capped item. External files use the same readable titles and sans typography as library notes. A dragged tab takes a shadow and paints over the tabs it crosses (`D60`).
- Ghost buttons and inactive tabs use `--muted` on hover, at 50% in dark mode, with `--foreground` text. The active tab keeps its workspace fill on hover, and a tab's close button uses the full muted hover fill. Toggles use the full muted fill for hover and pressed states. The new-note button, the find button and the overflow count are ghost `Button`s at `icon-xs`, `icon-xs` and `xs`.
- **The palette is the action surface.** A new action on the note, a tab, or the app goes in ⌘⇧P rather than into a bar. `SPEC.md` lists what it holds. ⌘P finds a note and ⌘⇧P acts on the app, on the tab that is showing, or on the note inside it, according to what the action reads.
- **A note in a list is `NoteLabel`**, in `src/components/notes/note-label.tsx`: the title, a pin when pinned, then the folder in `--muted-foreground` at `text-xs`, in one `gap-1.5` row, with the list's own fact after it, tags in the palette and `+1` in mentions. The create and rename rows read the action, then the filename it produces, in the item's gap. Tone and size carry the separation, so no middot, pipe, or dash sits between them. A second line is for a second kind of content, which is what a snippet and a mention's context line are.
- **The graph centres attention on its current note or hub.** The centre uses `--card`, `--foreground`, and its larger size. Surrounding nodes and overflow controls use `--background`, `--muted-foreground`, and a 1px border in `--border` at 50%. Nodes retain the badge's 4px corners. Hover changes the border and label to `--foreground` without changing the fill; a surrounding note or hub's connector also takes `--foreground`, from `--border` at rest. Fills stay opaque so connectors remain hidden behind nodes throughout transitions. Unresolved links have faint labels and dashed borders, with no hover treatment.
- **Floating surfaces share one recipe.** Suggestion menus and the link editor are `position: fixed`, `z-index: 50`, bordered, on `--popover`, with `--shadow-popover`, and the dropdown, context and combobox popups carry the same edge in their components. Menus clamp to the viewport rather than overflowing it.
- **A chord on screen is drawn by `Chord` from a hotkey, never typed as a glyph.** `src/components/chord.tsx` formats it for the running platform, so `Mod+Shift+N` renders `⌘⇧n` here and `ctrl+shift+n` where the symbols do not exist. A surface that already names an action, such as a palette row, finds its chords through `useChordsByName` instead of carrying them.
- **A bar control's tooltip names its action and carries its chords.** For an icon-only control the name is its accessible name: `new note`, `find a note`, `edit tags`, `focus mode`. `BarButton` in `src/components/bar-button.tsx` is that control, and takes the name, the glyph and the handler. For a chip whose label is a fact, the tooltip names the action behind it: `3 mentions` opens `show mentions`. A binding registered in another file is found through `useChordsByName` under that name, so the tooltip and the palette row read one registration and a control with no binding shows the name alone; one registered beside the tooltip shares its constant instead. A tab and a tag chip are their own label and carry none.
- **Shortcuts live in `README.md`.** That table is the one a person looks up, so it is the one that gets extended. Adding a shortcut here as well is how the two drift.

## The editor surface

- The caret takes `--foreground`, and selection takes `--selection`.
- The empty-document placeholder renders through `p.is-editor-empty:first-child::before` on `--faint`, and never as a real node.
- **The reading surface takes no colour of its own** (`D40`). Typeset reads the `--color-*` tokens the `@theme inline` block already emits, so the note is on the palette with nothing repointed. `src/styles.spec.ts` asserts the two roles it derives resolve to a token, and that every `::marker` paints from the muted one.
- **Bullet and ordered lists come from Typeset.** Markers, indentation, and the space between items are its at every depth, and a marker steps disc, circle, then square with depth. `src/styles.css` adds two things. `li > p` loses its block margins so a one-line item stays on one line. And where a node view puts a wrapper between a list item and its content, Typeset's nested step is restated at the shape that wrapper leaves behind, since the block would otherwise take the gap that separates top-level blocks: a task item's content div for a list or a blockquote, and `.code-block-wrapper` for a fence. `src/styles.spec.ts` reads both steps out of the vendored file, so a re-fetch cannot leave them apart.
- Inline code and code blocks share `--card` on screen. A code span uses the mono at `0.9em` with a derived radius. Its colour is pinned to `--foreground` rather than inherited (`D40`).
- **Task lists** use flex rows with zero paragraph margins and hand-drawn checkboxes locked to the first text line: a `1em` box with a `1.5px` border, `--radius-sm` radius, filled with the primary when checked and cut to lucide's check with a `clip-path` polygon, since a mask does not survive the PDF an export writes. A checked item goes muted and struck through without lowering its content's opacity. Every selector reaches a row as `ul[data-type="taskList"] > li` (`D39`). The list is padded like any other list and the row is pulled back by the checkbox column, so text lands at `1.9em` whatever the list kind and at `3.8em` one level in. The gap puts the box's right edge on `0.75em`, the column a disc paints in, and the pull-back cancels box plus gap so the text does not follow. All three are `em`, so the ladder holds when text is scaled, and `src/styles.spec.ts` asserts the pull-back cancels exactly the box and the gap.
- **Tables come from Typeset.** It separates rows, and the lines between cells are drawn here on `--typeset-rule`, the one hairline the quote edge, the divider and the footnote rule also use. There is no outer edge, so a table ends where its content does rather than sitting in a box, and the header drops the rule above it and reads as labels over the columns. A table sizes to its content, and one too wide scrolls inside `.tableWrapper` rather than moving the note.
- **Images** cap at `320px` tall, take `--radius-md`, and show a `--ring` outline when selected.
- **Every link draws one underline, and its style says where it goes.** Link text inherits the surrounding color and weight at rest and uses `--primary` on hover. Links share a 1px underline at the same offset, in the current color at 30%, strengthening to full on hover. Dashed inside the library, for a wikilink and for a markdown link whose destination is a note; solid out of it. Not `border-bottom`, which cannot break for a descender and sits at the box edge rather than on the font's metrics. The cursor is a pointer on all of them because a click follows all of them. Where a link goes is shown on hover, in a panel on the popover's surface carrying the url and the way into it, since the destination has nowhere else to appear.
- **Code blocks** sit on `--card` at `--radius-md`, in `--font-mono`, and reveal their toolbar (copy, language picker) on hover or focus-within. The native language picker fits the selected label, with the same height and horizontal padding as copy. An invisible label supplies its width without reserving space for a longer option.
- **Moving blocks adds nothing to the surface** (`D71`). There is no handle and no gutter: what moves is what is selected, and the gesture is the one text already uses. While a drag is in flight a copy of what is held follows the pointer on `--background` under the tab drag's `0 2px 8px rgb(0 0 0 / 0.18)` (`D60`), the source dims where it sits, and a `--primary` bar 2px wide and `1em` tall stands where it will land, which is the drop cursor CodeMirror draws. The copy hugs what it holds under the block's width, so a long paragraph wraps as it did, and it sits `16px` below and right of the pointer so the bar stays in view. It sits in the line as a zero-width inline box, so nothing shifts as it moves.
- **A note prints as the editor draws it.** Export pdf paginates a copy of the surface in the light palette on white paper, at the same 16px, with the same faces, links, task boxes and tables. The print side changes only what paper forces: a fence takes `--muted` while inline code retains `--card`, long code lines wrap, a table wider than the column shrinks to it, and paragraphs, fences, tables, quotes and images keep to one page while a heading travels with the block after it. Page margins are an inch above and below and whatever the paper has left beside the surface's 672px, 0.75in on Letter, so the text block is the editor's column on every paper.
- **Find matches** paint on the primary ink as a translucent fill, and the active match adds an outline.
- **Source mode** strips that card and toolbar: one bare, transparent, wrapping code block inheriting the fenced-code `0.875rem` size and `1.5` line-height, so ⌘E reads as the same document rather than a different screen.
- **A gone file** shows a destructive `Alert` at the top of the pane, in the note's column so its edges match the text below, and above the scroller so it stays while the note scrolls: "this file is gone" over "Nothing here is being saved, so copy what you need".
- **A note that changed on disk under overlapping edits** shows the same destructive `Alert` in the same place: "this note changed on disk" over "Your unsaved edits overlap the change, so nothing saves until you review them", with one outline button in its action slot, "review". A stash that could not be written adds its reason after that sentence.
- **A save that failed** shows the same destructive `Alert` in the same place, "this note could not be saved" over the reason, until a later write lands. Saving that succeeds is unmarked (`D87`).
- **The review** replaces the editor pane the way graph view does, in the same `max-w-2xl` column with the editor's padding, and nothing animates the swap. It lists the places that changed on both sides in order. Paragraphs that combined on their own sit between them as muted context, and a run past six lines folds behind a link `Button` reading "n unchanged lines".
- **Review text takes the note's type.** The quoted text sits inside the `.typeset-note` preset, so context, sides and the result box take the note's face, size and leading from the same rules as the editor. A place whose lines are one heading declares `data-heading="1"` and takes the h1 scale.
- **A place is two sides and a result.** "on disk" and "mine" are read-only blocks on the card surface, each with a ghost "use this" whose accessible name starts with the visible label and names the side. Under them sits one "result" `Textarea` at the sides' radius, labelled by a `Label`, empty until a side is used or the user types, with the placeholder "use one side above, or write the result". A side with nothing reads "nothing" in the muted ink. When typing has removed every overlap the header is an `Empty` reading "your edits no longer overlap the change on disk" over "Resolve applies both".
- **The review footer** holds "resolve", a ghost "back", the reason resolve waits in tabular figures ("2 of 2 still need a result", then "Every place has a result"; a used empty side counts), and the two chords drawn by `Chord` inside `KbdGroup`s. Opening puts focus on the first result; Esc goes back and returns focus to "review"; ⌘⏎ resolves and returns focus to the note. No toast follows; a save that lands is unmarked.

## Copy

- Prose is a description, an alert body, help text or an error reason. Uppercase is `text-transform` on an xs section label (palette groups, the graph legend, the review's block labels), never in a string and never over a note title.
- Errors reach the user in two parts: what failed, in the app's copy, as the title, and why, from the error, as the description, through `reasonOf` in `src/lib/ui/failure.ts`. The title is lowercase and names the action, written at the call site; the reason comes from the typed failure or the schema that raises it, as a sentence without an error number.
- **An empty state is `Empty`: a title, a description, and an action slot, at the sizes the component sets.** Find with no results reads `nothing found` over `Try different words or remove a filter`, and actions with none reads it over the chord that finds a note. A pending palette search with no previous rows keeps its results area empty until the read completes, unless the index is still scanning, when that area reads `indexing notes...` in the muted paragraph the palette's other waits use. A completed, unfiltered search with no results uses the create row in place of an empty state.
- A pane or screen that could not load is the same `Empty`, with the failure's two parts as its title and description and the retry as an outline button in its action slot.
- The welcome screen, shown when no tab is open, carries the mark beside one column containing the wordmark, "write another note", and the new-note and search actions. It keeps its own markup because it introduces the app rather than reporting missing content.
- Name what a control does rather than what it is. The palette entry is "move to folder", not "folder".

## Accessibility

- **`command.tsx` departs from upstream on purpose.** The sr-only `DialogHeader` sits inside `DialogContent`, because the content is portalled and upstream's placement leaves `aria-labelledby` pointing at a node outside the dialog.
- Focus is visible on every interactive element. A shadcn control keeps upstream's `focus-visible` ring, which recolors the border it declares. A `Badge` rendered as a button is the one that arrives without `outline-none`, since upstream never expects a badge to take focus, so the call site adds it or WebKit draws its own ring outside the app's. A control the app draws itself has no such border, so it shows `outline: 2px solid var(--ring)` at `outline-offset: 2px`. Where the focusable element only labels a larger surface, which is the tab strip's case, that surface takes the mark through `has-[:focus-visible]` and takes it inset, since the strip scrolls and would clip an outset one. `src/styles.spec.ts` gates the rule: anything setting `outline: none` or `appearance: none` has to carry a `:focus-visible` rule for the same selector.
- Autocorrect and autocapitalize are off in the editor, which removes the platform's blue underline.
